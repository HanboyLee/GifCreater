本文件用于统一记录、追踪与维护项目的所有产品需求及功能迭代。后续新增需求时，直接在此文档中进行追加与版本迭代更新。

## v2.0 需求基线 (已实现)

### 1. 核心业务需求
- [x] **多帧拼图自动/半自动切片**：
  - [x] 支持常见 4x4、3x3、6 帧长图等拼图切片。
  - [x] 自动探测黑边、白边与分割线，具备智能吸附算法。
  - [x] 提供可视化红色分割线交互拖拽微调，像素级调节行/列分界。
- [x] **实时尺寸与比例标注**：
  - [x] 实时计算切片单格像素尺寸与标准宽高比（如 1:1, 16:9, 9:16, 4:3, 3:2 等）。
- [x] **动图生成与播放**：
  - [x] 界面内置播放器，支持原地播放/暂停、滑动条控制、帧率调节。
  - [x] 支持常规正向循环与往复乒乓循环（Boomerang）。
- [x] **格式与尺寸规范导出**：
  - [x] 导出为 GIF 或 WebP。
  - [x] 提供「微信表情包模式」，强制约束长边尺寸与压缩体积（严格 <= 500KB）。
- [x] **帧管理能力**：
  - [x] 底部胶卷缩略图展示，支持单帧删除与恢复已删帧。

### 2. 工程与交付需求
- [x] **绿色单文件运行**：支持免安装单一可执行文件运行（Windows x64 EXE）。
- [x] **零配置本地输出**：生成过程切片与导出结果统一归档至本地目录。

## 质量门禁需求 (v2.1 规范引入) (已实现)

- [x] **测试驱动开发 (TDD)**：所有核心算法与功能逻辑均需具备可复现的单元测试用例。
- [x] **覆盖率硬指标**：核心业务模块单测覆盖率需达到 **90% 以上**。
- [x] **CI/CD 职责分立与版本 Tag 自动化发布体系**：
  - [x] **CI 持续集成门禁（推送至 main/PR 时触发）**：流水线自动执行文档基线同步校验、Ruff 静态语法 Lint 并阻断低于 90% 覆盖率的代码合入。
  - [x] **CD 持续交付与打包（推送 `v*` Tag 或手动调度触发）**：专责调用 PyInstaller 自动编译独立 Windows EXE、压缩 ZIP 并发布带有规范英文 Release Notes 的正式 GitHub Release，彻底终结每次 push 频繁打包浪费算力与版本混淆的缺陷。
  - [x] **支持随时手动按需构建（workflow_dispatch）**：开发者可在 GitHub Actions 界面一键手动触发全套测试与打包验证。

## v3.0 现代桌面客户端体验升级需求 (已实现)

### 1. 核心定位与设计诉求
- [x] 针对原有 Tkinter 客户端在 UI 表现力较弱、交互体验较单薄的痛点，在**坚持“100% 本机算力、零云端依赖、离线独立运行”**的根本前提下，全面重构 UI 展示层，打造媲美现代操作系统原生质感的专业动图工坊。

### 2. UI 视觉表现力需求
- [x] **现代化设计语言 (Fluent Design)**：
  - [x] 采用 Windows 11 风格的现代设计语言，引入亚克力 (Acrylic) / 云母 (Mica) 视觉层次；
  - [x] 全局控件统一具备现代圆角、层次阴影、悬停/点击微动效；
  - [x] 彻底解决高分屏 (High DPI / 4K / 2K) 缩放模糊与排版错位问题。
- [x] **主题自适应与切换**：
  - [x] 支持深色模式 (Dark Mode) 与浅色模式 (Light Mode)；
  - [x] 具备跟随操作系统主题自适应切换能力。

### 3. 高级交互体验需求
- [x] **流式画布与交互参考线**：
  - [x] 画布支持鼠标滚轮缩放与按住空格/中键拖拽平移大图；
  - [x] 网格切片参考线支持鼠标直接抓取、平滑拖拽微调，并在边缘提供磁吸辅助。
- [x] **专业级序列帧时间轴 (胶卷)**：
  - [x] 采用卡片式流式布局，支持鼠标横向滚轮浏览；
  - [x] 支持单选、Ctrl/Shift 多选废帧批量剔除，支持快捷键（Delete 键）删除；
  - [x] 废帧删除后提供“撤销/恢复”友好提示。
- [x] **丝滑的非阻塞异步体验**：
  - [x] 切片拆解、自适应调色板压缩、动图合成等重型计算必须在后台异步线程执行；
  - [x] 界面提供现代旋转环 (ProgressRing) 与实时步骤状态提示，**严禁任何操作导致界面“未响应”或假死**；
  - [x] 操作结果采用现代气泡通知 (InfoBar) 呈现，取代生硬阻塞的系统弹窗。

### 4. 架构与工程继承需求
- [x] **核心算法 100% 复用与本地化**：
  - [x] 严格继承 `gif_tool.py` 中经过严格测试的图像切片、去黑边、微信表情包 ≤500KB 压缩算法；
  - [x] 计算 100% 在本地 CPU 完成，不产生任何远程网络通信与数据外泄。
- [x] **面向未来演进的专案文件夹层级规范**：
  - [x] 不局限于当前代码，全面规划支撑未来迭代与功能扩展的标准文件夹体系；
  - [x] 聚焦高内聚、低耦合的**文件夹层级（Directory Level）**划分，涵盖文档中心 (`docs/`)、核心源码 (`src/`)、静态资源与主题 (`resources/`)、测试分类套件 (`tests/`)、工程脚本 (`scripts/`) 与本地归档 (`output/`)；
  - [x] 确立 **PyQt6 + PyQt-Fluent-Widgets** 作为现代 UI 统一技术基线；
  - [x] 彻底淘汰原 Tkinter 遗留代码，专案轻装前行；
  - [x] 采用渐进式落地策略：优先攻克高颜值 Fluent 交互界面、深浅色主题与异步任务，预留 `config/` 与 `i18n/` 目录骨架。
- [x] **质量门禁与交付体系**：
  - [x] 维持单测行覆盖率 ≥ 90% 的硬性门禁；
  - [x] 维持单文件 Windows EXE 绿色打包与 GitHub Actions 滚动发布机制。

## v3.1 平台预设与表情包配文增强需求 (已实现)

- [x] **零侵入设计 (Optional)**：
  - [x] 文本输入框默认留空；留空时保持原画切片输出，0 额外计算开销；
  - [x] 用户输入文本时，原地播放器与导出渲染图层实时同步白字黑边预览。
- [x] **画布自由拖拽与九宫格对齐**：
  - [x] 鼠标在画布上可直接抓取文字图元自由拖动，像素级放置到画面任意角落；
  - [x] 支持 3x3 九宫格一键快捷对齐（顶部居中、底部居中、正中央等）；
  - [x] 坐标系统采用相对比例（0.0~1.0），确保多分辨率与导出尺寸下位置一致。
- [x] **任意角度旋转 (-180° ~ +180°)**：
  - [x] 支持连续角度滑块调节，带 0° 中心吸附；
  - [x] 提供 `-15°`（动感倾斜）、`0°`、`15°`、`45°` 常用表情包角度快捷按钮；
  - [x] 采用双三次插值抗锯齿旋转，杜绝字体边缘锯齿。
- [x] **色彩、透明度与边框深度定制**：
  - [x] **文字颜色与透明度**：支持 Fluent 拾色器及 0%~100% 透明度调节（支持半透明水印）；
  - [x] **描边轮廓定制**：支持描边颜色拾取、0~10px 描边粗细调节（0 为无边框）；
  - [x] **爆款风格一键模板**：内置经典黑白、动感荧光黄、高能爆红、透明水印等快捷模板。

### 2. 平台导出预设管理器 (Preset Selector)
- [x] **统一 Fluent 下拉预设选择器**：
  - [x] 升级现有的散落单选框为带有规格说明的高扩展性 ComboBox；
  - [x] 预设内置：
    - [x] `💬 微信表情包 (1:1)`：强制约束最长边 $\le 240\text{px}$、文件体积 $\le 500\text{KB}$（512,000 字节）、五阶调色板自适应衰减；
    - [x] `📱 小红书 / 社交动态 (3:4)`：竖版画幅自适应居中补充背景；
    - [x] `🌟 原画超清 GIF`：无损原始单格尺寸与 256 色量化；
    - [x] `⚡ 高保真 WebP`：体积减半的高压缩比现代网页格式。

## v3.4 交互细节与品牌视觉精细化规范 (已实现)

### 1. 动图导出帧间隔精度与全平台往复一致性规范 (v3.4.1)
- [x] **帧间隔与末尾停顿高保真输出 (Duration Fidelity)**：
  - [x] 导出引擎必须 100% 尊重用户在界面配置的帧间隔（`duration`，毫秒）与末尾停顿时间（`end_pause`，毫秒）；
  - [x] 严禁任何导出预设（包括微信表情包预设）进行任何形式的暴力截断（如强行限制在 120ms）或尾帧时间抹平；
  - [x] 支持标准的 GIF89a 规范量化对齐：将输入毫秒数对齐为 10ms 的整数倍（四舍五入），并设置严格的物理下限 $\ge 20\text{ms}$，防止浏览器和播放器发生 100ms 降级。
- [x] **全预设往复（Boomerang）行为一致性**：全平台各导出预设均支持往复动画生成。

### 2. 智能网格线投影波谷吸附与中心对齐规范 (v3.4.2)
- [x] **AI 拼图分镜缝隙自动居中 (Gutter Center Snapping)**：
  - [x] 针对 Midjourney / SD / Flux 生成的多格拼图、漫画分镜等非绝对等宽等高素材，切片引擎必须具备智能识别分镜留白缝隙（Gutter / Margin）的能力；
  - [x] 严禁简单依赖数学几何等分；必须通过投影积分分析，在理论等分点局部窗口内搜索低信息量/背景波谷，并将切线**绝对锁定在波谷带的物理中位线（Centerline）**，杜绝切线压在分镜边缘或人物手脚；
  - [x] 原生支持 RGBA 透明通道背景判定，透明分镜缝隙优先识别。

### 3. 官方品牌视觉标识与图标系统规范 (v3.4.3)
- [x] **统一品牌视觉心智 (Visual Identity)**：
  - [x] 确立「极简双态几何切片」官方品牌 Logo（2×2 模块切片与动图循环箭头咬合，青蓝至荧光绿 Fluent 渐变，钛黑磨砂圆角卡片底板）；
  - [x] 彻底摆脱 Windows 默认空白应用图标与 Python 脚本共享图标状态。
- [x] **Windows 工业级多分辨率适配 (Multi-Res ICO)**：
  - [x] 图标资产必须包含 `16×16`、`24×24`、`32×32`、`48×48`、`64×64`、`128×128`、`256×256` 完整 Mipmap 尺寸链，满足不同 DPI 缩放下的像素级清晰度；
  - [x] 支持 Windows 原生 `AppUserModelID` 独立任务栏进程绑定；
  - [x] PyInstaller 打包必须将官方图标内嵌为 `GifCreater.exe` 文件徽标。

## v3.5+ 长期规划：Prompt 收集器与 Agent 生图工作流引擎 (规划中 / 待启动)

### 1. 业务背景与用户价值
用户在创作分镜动图时，工作链路的最上游通常是 **“如何写出优质的 AI 生图 Prompt（连环画/分镜/多格动作）”**。为实现用户在平台内**“从 0 到 1（从一句话灵感到最终动图成品）”**的完整创作闭环，需在工坊内打造一体化提示词生态。

### 2. Prompt 收集器 (Prompt Collector & Knowledge Base)
- [ ] **结构化增删改查 (CRUD)**：
  - [ ] 支持用户收藏、新建、编辑、删除与复制优质生图 Prompt；
  - [ ] 结构化字段支持：Prompt 正向词、Negative 负向词、适用生图模型（Midjourney / Flux / SDXL / DALL-E 3）、画幅比例（`--ar 16:9`、`1:1`）、分镜网格语法（如 `--grid 2x2`、`four-panel comic`）；
- [ ] **标签化检索与管理**：
  - [ ] 支持按风格标签（二次元、像素风、黏土风、3D写实）与动作分类检索；
  - [ ] 支持本地 JSON/Markdown 格式的导入与导出备份。

### 3. Agent API 智能规划与 Prompt 链生成 (Agent Workflow Engine)
- [ ] **多模型 Agent API 灵活接入**：
  - [ ] 支持配置主流大模型 API（OpenAI / Claude / Gemini / DeepSeek 等），支持自定义 Base URL 与 API Key，数据 100% 存储在用户本地配置。
- [ ] **标准化生成流程规范 (Prompt Generation Pipeline)**：
  - [ ] 系统内置分镜生图提示词生成规范与流程协议：
    - [ ] 步骤 1：**灵感输入**（用户输入一句话剧情或角色动作）；
    - [ ] 步骤 2：**角色一致性与视觉风格锚定**（锁定主角外貌、服装、发型）；
    - [ ] 步骤 3：**连贯分镜时序动作分解**（分解为 1~16 格连续动作步骤）；
    - [ ] 步骤 4：**目标生图模型语法封装**（自动适配 Midjourney 的权重、参数与网格指令）；
    - [ ] 步骤 5：**最终交付与一键复制**。
- [ ] **平台从 0 到 1 终极闭环愿景**：实现灵感输入 -> 分镜提示词 -> AI生图素材 -> 拼图切片 -> 表情包交付的全自动化链条。
