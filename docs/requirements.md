# 需求文档 (Requirements Document)

本文件用于统一记录、追踪与维护项目的所有产品需求及功能迭代。后续新增需求时，直接在此文档中进行追加与版本迭代更新。

---

## v2.0 需求基线 (已实现)

### 1. 核心业务需求
1. **多帧拼图自动/半自动切片**：
   - 支持常见 4x4、3x3、6 帧长图等拼图切片。
   - 自动探测黑边、白边与分割线，具备智能吸附算法。
   - 提供可视化红色分割线交互拖拽微调，像素级调节行/列分界。
2. **实时尺寸与比例标注**：
   - 实时计算切片单格像素尺寸与标准宽高比（如 1:1, 16:9, 9:16, 4:3, 3:2 等）。
3. **动图生成与播放**：
   - 界面内置播放器，支持原地播放/暂停、滑动条控制、帧率调节。
   - 支持常规正向循环与往复乒乓循环（Boomerang）。
4. **格式与尺寸规范导出**：
   - 导出为 GIF 或 WebP。
   - 提供「微信表情包模式」，强制约束长边尺寸与压缩体积（严格 <= 500KB）。
5. **帧管理能力**：
   - 底部胶卷缩略图展示，支持单帧删除与恢复已删帧。

### 2. 工程与交付需求
1. **绿色单文件运行**：支持免安装单一可执行文件运行（Windows x64 EXE）。
2. **零配置本地输出**：生成过程切片与导出结果统一归档至本地目录。

## 质量门禁需求 (v2.1 规范引入)

1. **测试驱动开发 (TDD)**：所有核心算法与功能逻辑均需具备可复现的单元测试用例。
2. **覆盖率硬指标**：核心业务模块单测覆盖率需达到 **90% 以上**。
3. **CI/CD 自动化验证与全自动发布**：
   - 流水线自动执行单元测试并阻断低于 90% 覆盖率的构建。
   - 每次代码推送至 `main` 分支并通过 90% 覆盖率门禁后，全自动更新发布 `latest` 绿色版本，无需手动打 Tag。
   - 依然支持推送 `v*` Tag 触发正式版本归档发布。

## v3.0 现代桌面客户端体验升级需求 (已实现)

### 1. 核心定位与设计诉求
针对原有 Tkinter 客户端在 UI 表现力较弱、交互体验较单薄的痛点，在**坚持“100% 本机算力、零云端依赖、离线独立运行”**的根本前提下，全面重构 UI 展示层，打造媲美现代操作系统原生质感的专业动图工坊。

### 2. UI 视觉表现力需求
1. **现代化设计语言 (Fluent Design)**：
   - 采用 Windows 11 风格的现代设计语言，引入亚克力 (Acrylic) / 云母 (Mica) 视觉层次；
   - 全局控件统一具备现代圆角、层次阴影、悬停/点击微动效；
   - 彻底解决高分屏 (High DPI / 4K / 2K) 缩放模糊与排版错位问题。
2. **主题自适应与切换**：
   - 支持深色模式 (Dark Mode) 与浅色模式 (Light Mode)；
   - 具备跟随操作系统主题自适应切换能力。

### 3. 高级交互体验需求
1. **流式画布与交互参考线**：
   - 画布支持鼠标滚轮缩放与按住空格/中键拖拽平移大图；
   - 网格切片参考线支持鼠标直接抓取、平滑拖拽微调，并在边缘提供磁吸辅助。
2. **专业级序列帧时间轴 (胶卷)**：
   - 采用卡片式流式布局，支持鼠标横向滚轮浏览；
   - 支持单选、Ctrl/Shift 多选废帧批量剔除，支持快捷键（Delete 键）删除；
   - 废帧删除后提供“撤销/恢复”友好提示。
3. **丝滑的非阻塞异步体验**：
   - 切片拆解、自适应调色板压缩、动图合成等重型计算必须在后台异步线程执行；
   - 界面提供现代旋转环 (ProgressRing) 与实时步骤状态提示，**严禁任何操作导致界面“未响应”或假死**；
   - 操作结果采用现代气泡通知 (InfoBar) 呈现，取代生硬阻塞的系统弹窗。

### 4. 架构与工程继承需求
1. **核心算法 100% 复用与本地化**：
   - 严格继承 `gif_tool.py` 中经过严格测试的图像切片、去黑边、微信表情包 ≤500KB 压缩算法；
   - 计算 100% 在本地 CPU 完成，不产生任何远程网络通信与数据外泄。
2. **面向未来演进的专案文件夹层级规范**：
   - 不局限于当前代码，全面规划支撑未来迭代与功能扩展的标准文件夹体系；
   - 聚焦高内聚、低耦合的**文件夹层级（Directory Level）**划分，涵盖文档中心 (`docs/`)、核心源码 (`src/`)、静态资源与主题 (`resources/`)、测试分类套件 (`tests/`)、工程脚本 (`scripts/`) 与本地归档 (`output/`)；
   - 确立 **PyQt6 + PyQt-Fluent-Widgets** 作为现代 UI 统一技术基线；
   - 彻底淘汰原 Tkinter 遗留代码，专案轻装前行；
   - 采用渐进式落地策略：本次优先攻克高颜值 Fluent 交互界面、深浅色主题与异步任务，预留 `config/` 与 `i18n/` 目录骨架。
3. **质量门禁与交付体系**：
   - 维持单测行覆盖率 ≥ 90% 的硬性门禁；
   - 维持单文件 Windows EXE 绿色打包与 GitHub Actions 滚动发布机制。
