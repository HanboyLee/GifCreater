# 🎞️ GifCreater 动画工坊 (v2.0 终极演进版) 产品与技术规格说明书

## 一、 产品定位与核心设计哲学

从原本单一的“16帧切片脚本”，全面进化为面向创作者与普通用户的**一体化多帧拼图拆解与动图精修工坊（Multi-frame & GIF Studio）**。

### 核心设计准则：
1. **单工作台流水线（No Broken Tabs）**：
   * 彻底摒弃割裂的多 Tab 模式，将「拆解 ➔ 预览 ➔ 删帧 ➔ 调速 ➔ 导出」整合在同一个主工作区中，一气呵成。
2. **随心输入，静默归档（Zero Output Friction）**：
   * 用户从任意位置选择图片（桌面、微信、下载区均可）；
   * 软件界面绝不强迫用户配置输出路径，所有成果全自动静默收纳至 exe 旁的 `output/`（若无权限则降级至用户图片目录）；
   * 界面提供显眼的【📂 打开成品目录】一键直达。
3. **真实过审级微信表情包预设**：
   * 针对微信自定义表情规范（硬指标：**文件大小 ≤500KB、长边 240px**），内置自适应调色板与智能压缩引擎，确保导出的动图 100% 能够直接添加进微信表情。
4. **所见即所得（WYSIWYG）**：
   * 切前：原图上实时叠加绘制网格分割虚线，切得准不准一目了然；
   * 切后：原地动图播放器流畅播放，循环模式（正序/乒乓）即预览即导出。

## 三、 核心模块与技术实现要点

### 1. 资产自动归档机制 (`output/`)
* 根目录结构：
  ```text
  output/
  ├── gifs/     # 动图成品归档
  └── frames/   # 拆解出的各组单帧文件夹
  ```
* 路径解析防坑策略：统一基于 `sys.executable`（冻结打包模式）或 `__file__`（开发模式）的绝对目录解析，防止通过右键启动时 CWD 漂移。
* 权限降级：若 exe 所在目录只读，优雅降级至 `%USERPROFILE%/Pictures/GifCreater/output`。

### 2. 动图实时播放器（Tkinter In-App Player）
* 架构：基于 `root.after()` 异步事件循环调度。
* 定时器安全防重入：在重载、切帧、改速或关闭时，必须调用 `after_cancel` 清理已排队的定时任务，避免回调累加造成加速死循环。
* 乒乓往复循环（Boomerang）：生成序列索引 `0, 1, ..., N-1, N-2, ..., 1`，并在导出时同样展开该序列。

### 3. 微信自定义表情规范压缩引擎
* 微信限制：硬指标 **长边 ≤240px、文件体积 ≤500KB**（非 1MB）。
* 自适应压缩策略：
  1. 画面等比缩放至最长边 240px；
  2. 适度提升播放速度至 80~120ms（表情包更灵动）；
  3. 采用 PIL 自适应调色板（Adaptive Palette，减少至 128 或 64 色）循环试探，确保输出严格控制在 500KB 安全线内。

### 4. 切前视觉辅助线（Visual Grid Overlay）
* 用户修改行列数（如 4×4、3×3）时，左侧画布在预览大图上实时叠加绘制清晰的分割参考线，用户一眼即可看清切割边界是否对准。

### 5. 交互式序列帧胶卷
* 拆解完成后，所有帧直接陈列在底部时间轴上；
* 选中某个废帧（如闭眼、AI 变形帧）可直接点击删除或右键删除，剩余帧立刻重新索引并实时联动给播放器与导出引擎。

### 3. 异步线程模型与防假死机制
* **痛点根治**：原有系统在微信表情包模式下执行 128/64/32 调色板自适应压缩时，若单帧较多会在主线程消耗 1~3 秒计算，导致界面卡顿。
* **重构机制**：
  1. 所有耗时计算均封装进 `QThread`（如 `SliceWorker` 与 `ExportWorker`）；
  2. Worker 运行期间通过 `pyqtSignal(int, str)` 向主线程抛出进度百分比和阶段文本；
  3. 主界面控件在任务期间自动切换为防重入只读状态，右下角渲染 Fluent `ProgressRing` 旋转环；
  4. 任务完成通过 `pyqtSignal(bool, str)` 唤起主线程的 Fluent `InfoBar` 现代轻量通知气泡（Success / Error）。

### 4. 迁移与向下兼容策略 (已由用户对齐确立)
1. **核心算法平滑桥接**：将现有核心图像处理逻辑平滑迁移至 `src/gifcreater/core/`，并在专案根目录保留 `gif_tool.py` 转发别名，确保历史测试用例与外部调用零中断；
2. **彻底清理历史包袱**：彻底移除原旧版 Tkinter 界面代码（`gui.py`），全面转向 `PyQt6` + `PyQt-Fluent-Widgets`，专案架构保持极致纯净；
3. **渐进式功能交付**：本次演进重点打磨高质量 Fluent 交互视窗、主题系统与异步防假死调度，同步建立 `config/`、`i18n/`、`resources/` 的规范文件夹层级骨架。

### 2. 核心文件夹职责与未来演进定位 (Directory Responsibilities)

1. **`docs/` (统一文档体系)**：
   * **定位**：依照 AGENTS.md 规范，作为全专案唯一允许存放文档的根目录。
   * **演进**：下设 `prd/` 承载各版本需求规格；`architecture/` 承载技术设计；`manuals/` 承载用户使用手册与版本更新说明。
2. **`src/gifcreater/` (生产代码体系)**：
   * **`core/`**：专职负责图像切分、去黑边算法、微信 500KB 调色板试探压缩、GIF/WebP 编码，严格保证纯 Python/C 运算，零 GUI 依赖；
   * **`ui/`**：专职负责 Fluent 现代窗口、可交互画布、时间轴胶卷等视觉交互；
   * **`config/`**：未来负责记录用户最后打开路径、最近使用的网格行列数、帧率偏好与自定义导出预设；
   * **`i18n/`**：未来承载国际化多语言翻译字典，支持中英双语即时切换；
   * **`utils/`**：收拢跨平台安全路径解析、目录自动创建与写入权限降级。
3. **`resources/` (静态资源与视觉资产)**：
   * 彻底避免以往将图标、图片硬编码或散落在代码目录的做法，集中收纳应用的 `.ico`、矢量 `.svg`、Fluent 样式表和开箱即用的预设模板。
4. **`tests/` (分类测试体系)**：
   * 将以往单文件测试拆分为 `unit/`（算法单元测试）、`integration/`（完整流程集成测试）和 `fixtures/`（动态数据生成），支撑长期严格执行的 `>=90%` 代码覆盖率门禁。
5. **`scripts/` (工程化与发布脚本)**：
   * 集中收纳自动化打包批处理脚本、图标多尺寸编译脚本等，保持根目录清爽。
6. **`output/` (本地运行时归档)**：
   * 本地计算与导出文件的专属收纳区，在 `.gitignore` 中强制忽略，杜绝污染 Git 仓库。
