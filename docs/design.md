# 🎞️ GifCreater 动画工坊 (v2.0 终极演进版) 产品与技术规格说明书

## 一、 产品定位与核心设计哲学

从原本单一的“16帧切片脚本”，全面进化为面向创作者与普通用户的**一体化多帧拼图拆解与动图精修工坊（Multi-frame & GIF Studio）**。

### 核心设计准则：
1. **单工作台流水线（No Broken Tabs）**：
   * 彻底摒弃割裂的多 Tab 模式，将「拆解 ➔ 预览 ➔ 删帧 ➔ 调速 ➔ 导出」整合在同一个主工作区中，一气呵成。
2. **随心输入，静默归档（Zero Output Friction）**：
   * 用户从任意位置选择图片（桌面、微信、下载区均可）；
   * 软件界面绝不强迫用户配置输出路径，所有成果全自动静默收纳至 exe 旁的 `output/`（若无权限则降级至用户图片目录）；
   * 界面提供显眼的【📂 打开成品目录】一键直达。
3. **真实过审级微信表情包预设**：
   * 针对微信自定义表情规范（硬指标：**文件大小 ≤500KB、长边 240px**），内置自适应调色板与智能压缩引擎，确保导出的动图 100% 能够直接添加进微信表情。
4. **所见即所得（WYSIWYG）**：
   * 切前：原图上实时叠加绘制网格分割虚线，切得准不准一目了然；
   * 切后：原地动图播放器流畅播放，循环模式（正序/乒乓）即预览即导出。

## 三、 核心模块与技术实现要点

### 1. 资产自动归档机制 (`output/`)
* 根目录结构：
  ```text
  output/
  ├── gifs/     # 动图成品归档
  └── frames/   # 拆解出的各组单帧文件夹
  ```
* 路径解析防坑策略：统一基于 `sys.executable`（冻结打包模式）或 `__file__`（开发模式）的绝对目录解析，防止通过右键启动时 CWD 漂移。
* 权限降级：若 exe 所在目录只读，优雅降级至 `%USERPROFILE%/Pictures/GifCreater/output`。

### 2. 动图实时播放器（Tkinter In-App Player）
* 架构：基于 `root.after()` 异步事件循环调度。
* 定时器安全防重入：在重载、切帧、改速或关闭时，必须调用 `after_cancel` 清理已排队的定时任务，避免回调累加造成加速死循环。
* 乒乓往复循环（Boomerang）：生成序列索引 `0, 1, ..., N-1, N-2, ..., 1`，并在导出时同样展开该序列。

### 3. 微信自定义表情规范压缩引擎
* 微信限制：硬指标 **长边 ≤240px、文件体积 ≤500KB**（非 1MB）。
* 自适应压缩策略：
  1. 画面等比缩放至最长边 240px；
  2. 适度提升播放速度至 80~120ms（表情包更灵动）；
  3. 采用 PIL 自适应调色板（Adaptive Palette，减少至 128 或 64 色）循环试探，确保输出严格控制在 500KB 安全线内。

### 4. 切前视觉辅助线（Visual Grid Overlay）
* 用户修改行列数（如 4×4、3×3）时，左侧画布在预览大图上实时叠加绘制清晰的分割参考线，用户一眼即可看清切割边界是否对准。

### 5. 交互式序列帧胶卷
* 拆解完成后，所有帧直接陈列在底部时间轴上；
* 选中某个废帧（如闭眼、AI 变形帧）可直接点击删除或右键删除，剩余帧立刻重新索引并实时联动给播放器与导出引擎。

### 3. 异步线程模型与防假死机制
* **痛点根治**：原有系统在微信表情包模式下执行 128/64/32 调色板自适应压缩时，若单帧较多会在主线程消耗 1~3 秒计算，导致界面卡顿。
* **重构机制**：
  1. 所有耗时计算均封装进 `QThread`（如 `SliceWorker` 与 `ExportWorker`）；
  2. Worker 运行期间通过 `pyqtSignal(int, str)` 向主线程抛出进度百分比和阶段文本；
  3. 主界面控件在任务期间自动切换为防重入只读状态，右下角渲染 Fluent `ProgressRing` 旋转环；
  4. 任务完成通过 `pyqtSignal(bool, str)` 唤起主线程的 Fluent `InfoBar` 现代轻量通知气泡（Success / Error）。

### 4. 迁移与向下兼容策略 (已由用户对齐确立)
1. **核心算法平滑桥接**：将现有核心图像处理逻辑平滑迁移至 `src/gifcreater/core/`，并在专案根目录保留 `gif_tool.py` 转发别名，确保历史测试用例与外部调用零中断；
2. **彻底清理历史包袱**：彻底移除原旧版 Tkinter 界面代码（`gui.py`），全面转向 `PyQt6` + `PyQt-Fluent-Widgets`，专案架构保持极致纯净；
3. **渐进式功能交付**：本次演进重点打磨高质量 Fluent 交互视窗、主题系统与异步防假死调度，同步建立 `config/`、`i18n/`、`resources/` 的规范文件夹层级骨架。

## 七、 v3.1 / v3.2 平台导出预设与表情包自由配文技术设计

### 1. 表情包高级文字叠加与变换无头引擎 (`core/caption.py` / `core/exporter.py`)
- **配置数据契约 (`CaptionConfig`)**：
  ```python
  @dataclass
  class CaptionConfig:
      text: str = ""
      pos_x_ratio: float = 0.5       # 相对水平中心 (0.0~1.0)
      pos_y_ratio: float = 0.88      # 相对垂直中心 (0.0~1.0)
      rotation_deg: float = 0.0      # 旋转角度 (-180° ~ 180°)
      font_size: Optional[int] = None
      text_color: Tuple[int, int, int, int] = (255, 255, 255, 255)      # RGBA 填充色与透明度
      stroke_color: Tuple[int, int, int, int] = (0, 0, 0, 255)          # RGBA 描边色与透明度
      stroke_width: int = 2                                             # 描边粗细 (px)
  ```
- **算法与渲染流水线**：
  1. **零开销旁路**：`if not config.text or not config.text.strip(): return image`；
  2. **透明图层文字绘制**：在与单行文字等宽高的透明临时图层上使用 `ImageDraw.Draw` 绘制带描边与 Alpha 的文字；
  3. **双三次插值抗锯齿旋转**：`rotated = text_layer.rotate(config.rotation_deg, expand=True, resample=Image.Resampling.BICUBIC)`；
  4. **精确居中锚定与 Alpha 复合**：
     - 计算中心点 `cx = int(w * config.pos_x_ratio)`, `cy = int(h * config.pos_y_ratio)`；
     - 计算粘贴左上角 `x = cx - rotated.width // 2`, `y = cy - rotated.height // 2`；
     - 使用 `Image.alpha_composite` 合成，彻底避免带透明度图层叠加时产生黑边或混色瑕疵。

## 十三、 导出管线帧时序与全格式一致性设计 (Frame Timing & Multi-Preset Consistency)

### 1. 痛点分析与设计反思
在旧版本实现中，微信表情包压缩逻辑错误预设了“表情包播放速度必须快”的偏见，在 `compress_wechat_gif` 中硬编码了 `120 if d > 160 else ...`，且在 `ExportWorker` 中强行抹平了尾帧停顿；同时，微信导出分支未接入 `generate_boomerang_sequence`。这导致用户在界面调试的帧间隔（如 350ms、500ms）及尾帧停顿在微信预设下完全失效，造成预览与产物脱节。

### 2. 帧时序保真架构演进
```text
UI 输入 (duration, end_pause, boomerang)
               │
               ▼
[ExportWorker.run 序列时序预处理]
  ├─ 构建完整帧时序: durations = [duration] * N, 且 durations[-1] = end_pause
  └─ 若 boomerang: generate_boomerang_sequence(frames, durations) 镜像扩展
               │
               ▼
分发各格式导出适配器 (Preset Handlers)
  ├─ wechat: compress_wechat_gif(frames, durations, ...)
  ├─ xiaohongshu: export_gif(frames, durations, ...)
  ├─ hd_gif: export_gif(frames, durations, ...)
  └─ webp: export_webp(frames, durations, ...)
               │
               ▼
[底质量化保护器 _quantize_duration]
  └─ max(20, round(d / 10) * 10)  (100% 遵循 GIF89a 10ms 颗粒度标准)
```

### 3. GIF89a 规范量化与浏览器兼容
- GIF89a 标准中图形控制扩展块（Graphics Control Extension）的 Delay Time 字段单位为 $1/100$ 秒（10ms）；
- 许多现代浏览器和图像查看器对 $<20\text{ms}$ 的帧延时存在历史兼容缺陷（会自动拉长至 100ms 导致播放变慢）；
- 导出引擎统一提供纯无头量化保护：`max(20, int(round(d / 10.0) * 10))`，既彻底保留用户的大延时配置（如 350ms $\to$ 350ms, 1500ms $\to$ 1500ms），又消除极限延时的播放器畸变。

## 十四、 智能网格线投影波谷吸附与中心对齐设计 (Projection Profile Valley Detection)

### 1. 痛点剖析与算法演进
传统简单的局部差分最大值算法（Edge Gradient）容易吸附在分镜黑/白边框与图像内容交界的边缘处，导致裁切时带入半边白条。新一代投影波谷吸附算法采用连续积分与中位线判定：

```text
[主体有效探测区域 Bounding Box]
               │
      ┌────────┴────────┐
      ▼                 ▼
[垂直投影剖面 Profile_X]  [水平投影剖面 Profile_Y]
      │                 │
      ├─ 累加透明度 Alpha 权重 (Alpha < 32 视为完全背景)
      ├─ 累加灰度色彩方差 (低方差连续带 = 背景/白槽/黑槽)
      │
      ▼
[理论等分点局部窗口 ±25% 扫描]
      │
      ▼
[波谷连通段提取: (gutter_start, gutter_end)]
      │
      ▼
[物理中位线提取: center_p = (gutter_start + gutter_end) // 2]
      │
      ▼
[网格参考线完美吸附于分镜槽隙正中央]
```

### 2. 核心数学模型与中位线计算
对于理论分割位置 $P_{nom} = \text{start} + k \times \frac{L}{N}$，定义局部探测窗口 $[P_{nom} - W, P_{nom} + W]$（$W = 0.25 \times \text{cell\_len}$）。
1. **能量打分函数**：对每个采样线 $p$ 计算能量 $E(p) = \text{Var}(p) + \text{MeanDiff}(p)$；
2. **波谷阈值分割**：在搜索窗口内提取最小能量 $E_{min}$，设定波谷判定阈值 $T_{valley} = E_{min} + \epsilon$；
3. **连通域中位线（Centerline）**：找到包含或最靠近 $P_{nom}$ 的连续波谷区间 $[p_a, p_b]$，最终分割线位置取其几何中点：
   $$P_{snap} = \left\lfloor \frac{p_a + p_b}{2} \right\rfloor$$
   这保证无论缝隙宽度为 2px 还是 20px，切线必然严格落于缝隙的正中，左右两侧留白完全对称。
