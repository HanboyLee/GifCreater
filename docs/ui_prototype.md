## 一、 UI 原型与交互生命周期契约 (UI Lifecycle Protocol)

为了杜绝“UI 凭感觉做、做完发现不符合预期、推倒重做”的低效循环，确立以下界面设计生命周期：

```text
  【第一阶段：HTML交互原型】       【第二阶段：用户审查拍板】         【第三阶段：代码实施】
  更新 docs/prototype.html   ───>  用户在浏览器点选体验审查清单 ───>  严格按原型对齐编写 PyQt6
  与 docs/ui_prototype.md          审查确认无误后方可推进             通过 90% TDD 与无头测试
```

1. **改界面必先改 HTML 交互原型**：
   - 任何按钮增删、面板重构、文字叠加交互，必须先在 **`docs/prototype.html`** 中实现动态渲染（支持所见即所得打字、滑块联动与深浅色模式）；
   - 在本 Markdown 文档中同步记录版本变更说明与 ASCII 架构图；
2. **审核清单对齐**：必须在原型文档末尾提供包含“布局合理性、交互无侵入、描边样式、深色对比度”的明确审查清单供用户审核；
3. **像素级真实还原**：代码实现阶段必须 100% 还原原型图中的控件层级与交互效果，严禁临场随意改动布局。

## 四、 核心改动与交互逻辑深度解析

### 1. 右侧新增「💬 表情包配文」卡片模块
- **零负担设计（Optional by Default）**：
  - 输入框默认留空。**留空时完全不影响原有切片流程**，0 额外开销，不改变原图像素；
  - 只要用户在输入框打字，画布中心的原地播放器即刻呈现“所见即所得（WYSIWYG）”的字样预览。
- **默认工业爆款样式**：
  - 预设提供：`经典黑边白字`（表情包最通用、任何复杂花哨背景下都能清晰可读）、`极简纯白底描边`、`顶部黑条弹幕字`；
  - 描边逻辑：白色填充文字，外圈以 2~3px 黑色高斯抗锯齿描边，保证在深色/浅色背景下均 100% 清晰。
- **自适应字号机制**：
  - 针对长边 240px 的微信表情，字号自动映射到最佳可读范围（22~28px），并随用户设置上下微调。

### 2. 右侧升级「📦 平台导出预设」选择器
- 将原有的三个单一 RadioButton 升级为 **带有详细规格说明的 Fluent 下拉选择器 (`ComboBox`)**：
  1. `💬 微信表情包 (1:1)` —— 目标 $\le 500\text{KB}$，长边 240px，五阶自适应调色板，保留透明度；
  2. `📱 小红书 / 社交动态 (3:4)` —— 目标高画质，竖向画幅自适应居中补充背景；
  3. `🌟 原画超清 GIF` —— 原始切片像素尺寸无损导出，256 色量化；
  4. `⚡ 高保真 WebP` —— 体积极小、色彩无损、支持现代网页与社交软件。

## 五、 用户审查要点清单 (Review Checklist for Approval)

请用户对照以下 5 个关键维度进行审查与确认：

- [ ] **1. 布局结构一致性**：确认是否保留了您习惯的“左侧主工作区 + 右侧垂直滚动面板”结构，未发生令人生疏的界面大变动。
- [ ] **2. 配文交互无侵入性**：确认“输入文字即加字，不输入文字则完全保持原汁原味导出”的零负担逻辑是否满意。
- [ ] **3. 表情包样式规范**：确认“经典黑边白字”是否契合您日常制作微信表情包的视觉预期。
- [ ] **4. 平台预设扩展性**：确认下拉选择器替代单选按钮是否更加直观，且能够清楚看到各平台的尺寸/体积限制说明。
- [ ] **5. 色彩与对比度**：确认深色模式下的卡片层级（背景 `#1a1a1a`、卡片 `#272727`、文字高对比 `#f0f0f0`）是否舒适。
