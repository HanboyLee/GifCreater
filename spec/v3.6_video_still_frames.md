# v3.6 视频静止帧 → 网格裁切 → 合并 GIF 立项规格书 (RFC)

> 状态：**立项已确认，实施中**（决策：两种模式都做 / PyAV / Fluent 模态对话框）。
> 路线图锚定：本规格对应 `docs/roadmap.md` v3.6 第 2 项「视频 → GIF」的前半段，提前拆为独立里程碑 **v3.6.0**；原「批量处理流水线」顺延为 v3.6.x。

## 1. 用户故事
1. 作为创作者，我导入一段 MP4/MOV/WebM/MKV 视频，在时间轴上拖动并逐帧微调，选出最合适的一张**静止帧**。
2. 我把这张静止帧送入工坊，用 **3×3 / 4×6 / 6×4 / 自定义**网格裁切，再合并为**单张 GIF**。
3. 我也可以不裁切：按网格格数（如 3×3=9 帧）从视频区间**均匀抽帧**，直接合并为 GIF。

## 2. 流程
```text
导入视频 ──> 静止帧调整(时间轴/逐帧/邻近帧)
                 ├─ 模式 A：设为静止帧 ─> 工坊画布(网格裁切) ─> 一键拆解合成 ─> GIF
                 └─ 模式 B：按网格抽帧 ─────────────────────────> 胶卷 ─> GIF
```

## 4. API 签名（`src/gifcreater/core/video_source.py`，无头）
```python
class VideoError(Exception): ...

@dataclass(frozen=True)
class VideoInfo:
    width: int; height: int          # 已应用旋转后的显示尺寸
    fps: float; duration_s: float; frame_count: int; rotation: int

def probe_video(path) -> VideoInfo
class VideoReader:                    # 上下文管理器
    info: VideoInfo
    def get_frame_by_index(self, index: int) -> Image.Image          # 帧级精确，RGB
    def get_frame_at(self, time_s: float) -> Image.Image
    def index_at(self, time_s: float) -> int
    def neighbors(self, index: int, radius: int = 3, max_edge: int = 96) -> list[tuple[int, Image.Image]]
    def sample_evenly(self, n: int, t_start=0.0, t_end=None, max_edge=None) -> list[Image.Image]
def grid_frame_count(rows: int, cols: int) -> int                    # rows*cols
```
- 输出统一 `RGB` PIL.Image，直接对接 `slice_image` / `export_gif`，**不修改**切片与导出算法。
- 越界时间/索引夹紧；无视频流/坏文件抛 `VideoError`（可读中文消息）。

## 5. 性能与约束
- 单帧 seek 解码目标 < 300 ms（1080p）；滑条防抖 80 ms，只保留最新请求，LRU 缓存最近 8 帧。
- 预览用缩放帧，确认进入裁切时才取全分辨率；批量抽帧可传 `max_edge`。
- 纯本地解码，无任何网络请求（符合纯本地计算隐私底线）。
- 色彩：首版按 BT.709 转 RGB，HDR/BT.2020 的色偏为已知限制。

## 6. 依赖与打包
- 新增 `av>=12`（PyAV，wheel 约 27 MB，自带 FFmpeg 库）；`GifCreater.spec` 使用 `collect_all('av')`。
- EXE 体积增量在 P4 实测并写入交付报告。

## 7. 测试策略

- 用例覆盖：元数据、帧级精确（颜色==帧号）、越界夹紧、坏文件、均匀抽帧、旋转、Worker 防抖/缓存/取消、对话框与主窗口端到端（模式 A、模式 B）。
