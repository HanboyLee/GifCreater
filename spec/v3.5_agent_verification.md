# v3.5 Agent 验车剧本

代码管流程与对错数字；Computer Use 管点界面；Jev 只管语义判断（Choice / Noul）。  
**不把 TypeSafe SDK 写入 GifCreater 运行时依赖。**

## 0. 启动哪份代码

验车目录必须是用户本机仓库 **`E:\GifCreater`**（不要只开 Orca 副本）。  
启动：`E:\GifCreater\run_gui.bat`。标题必须含 **v3.5**。

## 1. 代码门禁（必过，不问 Jev）

```text
python -m pytest tests/ --cov=src/gifcreater/core --cov=src/gifcreater/config --cov=gif_tool --cov-fail-under=90
```

失败：改代码，不要去点 GUI。

## 2. 进程内 E2E（pytest，Mock HTTP）

`tests/integration/test_v35_workbench.py`：注入 FakeProtector、假 `chat_completions`，点「完善」，断言正文。  
失败：改代码。

## 3. 真窗口（Computer Use 或人工）

1. 关掉旧窗口，启动 `run_gui.bat`
2. 看标题 v3.5；左栏应有 动图工坊 / Prompt，底部 设置
3. 点 Prompt：应有 网格、提示、完善、Prompt、复制、保存
4. 点设置：主题横排；API 表单

## 4. Jev 只问这三题（截图 + 控件文案作 state）

未接 API 时由 Agent 目视等价判断；有 Key 再换成 Jev 调用。

1. **Noul `nav_ok`**：左栏是否同时存在工坊、Prompt、设置？  
   否 → 改导航代码，不要继续点。
2. **Noul `prompt_page_ok`**：当前页是否为 Prompt 工作台（网格 + 提示 + 完善）？  
   否 → Choice 下一步：`click_prompt` / `fix_code`
3. **Noul `refine_looks_like_storyboard`**：完善结果是否为自然语言分镜、且无 `--ar`/`--grid`？  
   低置信度 → 停下来问人。

**Choice `next_action`**：`click_settings` | `click_prompt` | `click_refine` | `fix_code` | `pass`

不问 Jev：覆盖率、HTTP 状态码、sqlite 路径、标题字符串（代码断言即可）。

## 5. 失败处理

| 现象 | 动作 |
|------|------|
| 标题仍是 v3.0 | 开错目录，切到 `E:\GifCreater` |
| pytest 红 | 先修测试，不开 GUI |
| 完善超时/401 | 查设置 Key；测试里必须 Mock，禁止打真网 |
| Jev 低置信 | 问用户，禁止连点 |

## 6. 通过标准

- pytest 绿且覆盖率 ≥ 90%
- 真窗口标题 v3.5，三页能切
- Mock 完善能写入 Prompt 框
- 不上传图片、不代为生图
