# 02 - Vibe Coding 防作弊机制与 TDD 质量门禁 (TDD & Anti-Cheat Gate)

在 AI 辅助开发（Vibe Coding）模式下，AI 必须严格受制于本质量门禁。杜绝任何形式的代码腐化、测试作弊与虚假交付。

---

## 1. Vibe Coding 防作弊判定红线 (Anti-Slop & Anti-Cheat)

以下行为一经发现，立即判定为**严重违规并否决交付**：

1. **严禁虚假单测与琐碎断言**：
   - 严禁出现 `assert True`、`assert 1`、`assert x is not None` 等无实质校验的表面断言；
   - 严禁为了覆盖率而在测试中直接 Mock 掉被测核心函数本身；
   - 单元测试必须断言具体的数值边界、长宽尺寸、调色板颜色数、文件二进制头（GIF89a / WEBP VP8）及字节上限。
2. **严禁破坏原有功能与悄悄删减代码**：
   - 重构或修复 Bug 时，严禁随意删除原有合法功能或将原本复杂的异常处理简化为 `pass`；
   - 必须保持既有单元测试套件的持续绿灯。
3. **零磁盘大媒体污染红线 (Zero Disk Media)**：
   - 自动化测试中若需涉及图像数据，**必须在内存（RAM）中通过 `PIL.Image.new()` 动态生成微型测试图像**；
   - 严禁向 `tests/` 目录或 Git 仓库提交任何真实的 `.png`、`.jpg`、`.gif` 大体积文件；
   - 单测全部运行时间必须保持在 15 秒以内。

---

## 2. 90% 代码行覆盖率硬指标 (Coverage Gate >= 90%)

1. **覆盖率执行命令**：
   ```bash
   pytest tests/ --cov=src/gifcreater/core --cov=gif_tool --cov-report=term-missing --cov-fail-under=90
   ```
2. **门禁铁律**：
   - 核心算法层（`src/gifcreater/core/`）与根目录兼容垫片（`gif_tool.py`）的代码行覆盖率**必须严格达到 90% 以上**；
   - 若测试用例存在任何一个失败（Fail），或行覆盖率低于 90%，**严禁声明任务完成，CI/CD 流水线将直接阻断构建发布**。

---

## 3. 可验证的交付证据标准 (Verifiable Evidence Standard)

AI 在完成功能开发或缺陷修复后，**严禁使用“已修复”、“已经完成”等主观黑盒表述**。必须提供以下三项客观可核验凭证：

1. **完整的命令行输出凭证**：
   - 提供真实执行 `pytest` 的控制台输出片段，必须明确展示通过用例数量（如 `67 passed`）以及覆盖率表格（总覆盖率 $\ge 90\%$）。
2. **零运行时错误自检凭据**：
   - 控制台无语法报错、无未捕获异常、无废弃 API 警告。
3. **确定性复现指引**：
   - 说明如何通过具体命令行参数或界面操作步骤，单步复验该功能的有效性。
