# 04 - 微信表情包专项规格与调色板收敛准则 (WeChat Sticker Standards)

微信自定义表情包是 GifCreater 的核心杀手级场景。微信客户端对动图体积和尺寸有极其严苛的物理上限，必须通过确定性算法予以保证。

---

## 1. 微信表情包三大刚性硬指标 (Hard Invariants)

任何导出为“微信表情包”模式的 GIF 文件，必须同时满足以下三项物理红线：

1. **文件大小红线**：
   $$\text{FileSize} \le 500\,\text{KB} \quad (512,000\,\text{字节})$$
   超过 512,000 字节的动图将直接被微信移动端拒绝添加（报错“表情图片过大”）。
2. **像素尺寸红线**：
   $$\max(\text{Width}, \text{Height}) \le 240\,\text{px}$$
   保持原图比例等比缩放，最长边严禁超过 240 像素。若单格原图尺寸小于 240px，则保持原尺寸不进行放大。
3. **色彩与透明度保留**：
   - 必须保留透明通道（Alpha）；
   - 使用高质量重采样算法（`Image.Resampling.LANCZOS`）进行缩放，防止边缘锯齿。

---

## 2. 自适应调色板五阶阶梯衰减算法 (Adaptive Palette Ladder)

当遇到长帧序列或高噪点复杂图像时，单纯缩放尺寸可能仍会导致体积超过 500KB。系统必须执行五阶动态自适应调色板衰减试探：

```text
[等比缩放至 <=240px]
         │
         ▼
[第 1 阶: 128 色量化] ──(<= 500KB?)──> [成功退出]
         │ 否
         ▼
[第 2 阶: 96 色量化]  ──(<= 500KB?)──> [成功退出]
         │ 否
         ▼
[第 3 阶: 64 色量化]  ──(<= 500KB?)──> [成功退出]
         │ 否
         ▼
[第 4 阶: 48 色量化]  ──(<= 500KB?)──> [成功退出]
         │ 否
         ▼
[第 5 阶: 32 色极限量化] ──(保底输出，通知用户在胶卷中适当删减冗余废帧)
```

### 算法实现约束：
- 衰减逻辑必须封装在 `src/gifcreater/core/compressor.py` 中；
- 每次试探必须在内存二进制流（`io.BytesIO`）中测量实际编码体积；
- 严禁死循环，最多试探 5 阶后必须终止并输出最优产物。
